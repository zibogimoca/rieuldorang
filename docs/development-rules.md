# 개발 규칙

1. 문구와 자료는 `src/content/`, 표시 방식은 `src/components/`, 디자인은 `src/styles/`에서 관리합니다. 건물마다 화면 파일을 복사하지 않습니다.
2. 타입은 `src/types/`에서 정의합니다. 타입 오류를 `any`나 검사 비활성화로 숨기지 않습니다.
3. 자료는 `textContent`로 표시합니다. 소개 글에 HTML을 넣거나 `innerHTML`로 렌더링하지 않습니다.
4. 새 라이브러리는 기존 기능으로 해결하기 어려울 때만 추가합니다. 추가 이유와 실행 방법을 문서에 기록하고 lockfile을 함께 변경합니다.
5. 사진에는 대체 텍스트를 작성합니다. 링크·버튼은 키보드로 사용할 수 있어야 하고 모바일에서도 가로 스크롤 없이 읽을 수 있어야 합니다.
6. 비밀키, 개인정보, `.env`, 빌드 산출물, `node_modules`를 커밋하지 않습니다.
7. 구조나 작성 방법을 바꾸면 관련 `docs`도 같은 변경에서 수정합니다.

## 변경 확인

```sh
npm ci
npm test
npm run build
npm run dev
```

브라우저에서 공간·소개 이동, 상세 설명 펼치기, 모바일 너비, 키보드 포커스, 사진 대체 텍스트와 깨진 경로를 확인하세요. `npm test`는 원본 페이지의 이미지·이동 링크와 본문 인덱스를 검사합니다. 저장소에 자동화된 브라우저 테스트는 없습니다. 타입 검사·빌드 성공만으로 화면 검증을 대체하지 않습니다.

## 배포

정적 호스팅의 빌드 명령은 `npm run build`, 게시 디렉터리는 `dist`입니다. `preview`는 빌드 결과 확인용입니다. 실제 운영 배포와 도메인 연결은 호스팅 설정에서 별도로 진행합니다.
